# 协议与 I/O 模型

## TCP 是字节流

一次 `send` 可能只写入部分内容，一次 `recv` 也可能只读到部分内容。公共层的 `net_send_all` 持续写完；`net_receive_exact` 区分完整读取、起始 EOF 和消息中途截断，并处理 EINTR。服务端对单个连接的错误只关闭该连接，SIGPIPE 不会终止整个进程。

回显协议原样返回字节，没有隐含字符串结尾。单次客户端发送后 `shutdown(SHUT_WR)`，服务端读到 EOF 后完成输出，客户端仍能接收响应。标准输入交互客户端以 q / Q 或 EOF 结束，最后一个不带换行的片段也会发送。

`net_streams` 通过 dup 为读、写分别创建 FILE，避免在同一个更新流上切换读写时违反缓冲规则。它在成功与失败时都接管原描述符；调用者只需分别 fclose，不能再 close 原 fd。`HandleTCPClient` 则只借用 fd，关闭责任在调用者。

## 并发与背压

| 实现 | 待发送数据与事件处理 |
| --- | --- |
| select | 非阻塞 socket；队列有数据才订阅可写；检查 FD_SETSIZE |
| epoll LT | 按当前队列状态更新读写兴趣，保留未发送字节 |
| epoll ET | EPOLLET + EPOLLONESHOT；每轮有界处理后重新 MOD，继续通知尚未完成的 I/O |
| libevent 读写事件 | EV_PERSIST 事件按队列状态启停，共用流状态机 |
| libevent bufferevent | 输入高水位、输出上限和写低水位控制暂停 / 恢复读取 |

并发回显最多同时维护 128 个连接，流状态机每连接输出队列上限 64 KiB；bufferevent 的输入、输出各限制在 64 KiB。输出暂时写不完时暂停读取，防止慢读客户端造成无界内存增长。EOF 只表示不能继续读，已排队输出发送完成后才关闭连接。

流状态机每轮最多 64 次迭代，避免单个活跃连接独占事件循环。ET 使用 ONESHOT 重新订阅处理有界工作和背压；更改为普通 ET 时必须重新审视“读写直到 EAGAIN”的要求。可参考 [epoll 手册](https://man7.org/linux/man-pages/man7/epoll.7.html)与 [send 手册](https://man7.org/linux/man-pages/man2/send.2.html)。

## UDP

每个请求数据报对应一个相同内容的响应；`recvfrom` 返回 0 是有效的空数据报，不能当作连接关闭。服务端使用真实的源地址长度回复，地址链由 freeaddrinfo 释放。

客户端使用 connected UDP，由内核过滤来自其他地址 / 端口的数据报；检查响应长度、内容和截断标志。普通客户端等候约 1 秒；超时版本最多尝试 5 次，每次约 200 毫秒，包含实际重发。重试不能保证消息只执行一次，这里回显操作没有额外副作用。

客户端消息最多 65507 字节；这是本示例统一采用的 IPv4 UDP 载荷上界，实际可发送大小还受系统和路径约束。macOS 默认数据报限制可能更小。服务端接收缓冲区为 65536 字节。

## 投票协议

候选编号为 0..1000，计数为 uint64，保存在服务进程内存中；重启清零。查询不会增加计数。客户端与服务端必须选同一种编码和分帧组合。

| 目标后缀 | 分帧 | 消息体 |
| --- | --- | --- |
| bin | 两字节无符号大端长度；长度不含前缀 | 请求 4 字节、响应 12 字节 |
| text | 以 LF（`\n`）结尾；编码内容不含 LF | ASCII token 文本 |

二进制体：

| 偏移 | 长度 | 字段 |
| --- | --- | --- |
| 0 | 2 | 大端 header：magic 0x5400，查询位 0x0100，响应位 0x0200 |
| 2 | 2 | 大端候选编号 |
| 4 | 8 | 仅响应存在，大端完整 64 位计数 |

保留位、长度与候选范围均校验；编码按字节操作，不依赖 struct 布局或对齐。请求/响应精确为 4/12 字节，修复了旧版计数截断；请同时更新客户端和服务端，勿与旧的错误编码混用。

文本体示例：

```text
Voting v 23
Voting i 23
Voting v R 23 1
Voting i R 23 18446744073709551615
```

`v` 为投票，`i` 为查询，`R` 为响应标记。解析有明确的输入长度，不修改原缓冲区；拒绝额外字段、负数、嵌入 NUL 和数值溢出。应用层最多接受 500 字节消息体；超过应用缓冲区的帧被完整排空，避免下一帧错位。

通用 Framer 最长 65535 字节，按字节处理，允许空帧；空帧返回 0，EOF / 格式或 I/O 错误返回 -1，完整排空的超长帧返回其原始长度的负数。PutMsg 检查写入与刷新错误；分隔符版本禁止消息体内的 LF。投票应用不会把空帧当成有效请求。

## 算术协议

请求为 `1 字节数量 + N × 4 字节操作数 + 1 字节运算符`，响应为一个 4 字节结果。操作数和结果均为大端有符号 int32 的二进制补码编码，N 为 1..64，运算符为 `+`、`-`、`*`，从左到右执行。

服务端逐字段完整读取，并用 int64 中间值检查每一步是否超出 int32 范围。无效数量、截断、未知运算符或溢出只关闭当前连接；协议未定义错误响应。新版显式使用网络字节序，与旧版直接发送本机 int 的布局不兼容，需配套升级两端。

## 聊天协议

服务端以 LF 作为广播边界，先合并 TCP 片段再广播整行；对端 EOF 时广播剩余尾部字节。每行最多 2048 字节，最多 128 个工作线程槽位，线程参数在 join 完成前保持有效。客户端名称最多 16 字节，发送前添加 `[name] `，一行输入最多 1024 字节（包括换行）。

广播在锁内顺序执行非阻塞写；缓冲区无法继续接受整行时，断开该慢读连接，由拥有它的线程负责关闭。部分发送后被断开的客户端可能看到最后一行的部分内容。该示例没有历史记录、用户认证或重放语义。

## TLS 校验

TLS 客户端校验证书信任链，DNS 使用 `SSL_set1_host` 并单独设置 SNI，IP 使用证书 IP SAN 校验。名称校验和 SNI 是两项独立操作，可参考 [OpenSSL 名称校验文档](https://docs.openssl.org/3.0/man3/SSL_set1_host/)。

连接阶段使用约 5 秒期限；TLS 握手另有 5 秒期限，HTTP 传输总计 10 秒期限。WANT_READ / WANT_WRITE 使用 poll 等待正确方向，不忙等。响应要求正常的 TLS close_notify，未完整关闭的传输返回失败。
